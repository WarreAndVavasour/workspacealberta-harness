# @workspacealberta/wa-procurement-base

[English](README.md) | 中文

Workspace Alberta 的 Cohere 批量采购评审（`procurement_review_batch`）。

该工具通过固定工作池处理请求的商机：Cohere v2 基于调用方提供的证据为每个商机生成有依据的摘要，原生引用记录对照所提供的文档进行校验，每个请求的条目都有独立的结果。队列边界、模型与凭证均为部署配置。

## 插件

需要 `ctx.tools`（`inject: ['tools']`）。

### 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `apiKey` | — | 仅用于测试与手动运行的字面密钥；其他场景请使用 `apiKeyEnv`，勿将密钥写入配置文件。 |
| `apiKeyEnv` | `COHERE_API_KEY` | 每批次解析的凭证引用。 |
| `baseURL` | `https://api.cohere.ai`（未配置时 `COHERE_BASE_URL` 环境变量优先） | v2 端点基地址；每次调用追加 `/v2/chat`。 |
| `model` | `command-a-plus-05-2026` | v2 模型名称。 |
| `maxTokens` | `1024` | 每次合成调用的生成 token 上限。 |
| `concurrency` | `3` | 同时在途的最大合成调用数。 |
| `maxJobs` | `200` | 每批次接受的最大商机数；超限在任何 provider 调用之前失败。 |
| `maxRetries` | `2` | 可重试失败（429/5xx）后每个商机的重试次数。 |
| `retryBaseMs` / `retryMaxMs` | `200` / `5000` | 重试退避基数与上限（含服务端 retry-after 提示）。 |
| `maxDocuments` | `12` | 每次调用的证据文档数；超出的文档被丢弃并报告。 |
| `maxCharsPerDocument` | `6000` | 每个文档保留的字符数；超长文本被截断并报告。 |
| `maxImageBytes` | `20971520` | 每次调用解码后的图片字节总预算。 |

## 行为

每个商机携带各自的证据文本与可选的 base64 图片 data URL。原生 PDF 与视频没有直接的模型路径，会返回明确的不支持结果；超限或远程图片载荷在任何 provider 调用之前抛出。凭证按批次经凭证通道解析，绝不进入日志、转储或错误文本；携带凭证的请求绝不跟随重定向。Provider 失败映射为固定错误码（`COHERE_HTTP_429`、`PROCESSING_FAILED`）；含失败的批次属于部分覆盖，绝非完整评审。Fit 标签归调用方 agent 及其评审标准：需求的抽取不等于订阅方能力的验证。

## 模型体验

该工具渲染一行摘要（就绪/失败/取消计数）及各条目的规范值：摘要文本、已校验引用数、被拒引用数、截断标志、尝试次数与失败码。视觉解读以普通文本形式返回，不带页面引用；失去引用的关键主张由调用方升级处理，绝不自行修补。

#### KV 缓存影响

无直接失效；结果为每次调用的新工具输出。

## 已知限制与后续工作

- **证据由调用方提供**——工具仅对给定文本与图片进行合成，不自行抓取采购门户；请与采购 MCP 服务及官方公告配合使用。
- **无 PDF 或视频路径**——PDF 需要抽取/渲染步骤，视频需要带时间戳的帧采样；两者均为明确缺口，而非静默跳过。
- **图片预算按调用计算**——每次调用至多 20 张图片且在字节预算内；更大的证据集由 agent 拆分多次调用。
- **能力未经核实**——档案匹配仅比较所提供的记录；实时施工排期需要实时权威集成。
