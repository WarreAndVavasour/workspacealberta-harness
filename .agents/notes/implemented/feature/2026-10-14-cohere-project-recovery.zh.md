# Agent Note: 原生 Cohere 交付与持久项目检查点

Status: implemented

[English](2026-10-14-cohere-project-recovery.md) | 中文

## 问题

企业部署选择 OpenAI 兼容路由，而原生 Cohere v2 工作位于另一个分支。工具调用及其重放需要经过测试的统一部署路径。长期企业项目也需要跨轮次保留状态，不能依赖轮次级待办清单或始终运行的单次请求。

## 决策

产品覆盖配置选择位于 `https://api.cohere.com/v2` 的 `cohere-v2-chat`。恢复的适配器通过现有 pi-ai 接口转换流式计划、调用、结果及最终用量。HTTP 错误保留状态，因此可区分身份验证、速率限制与服务端失败。现有 MIT 声明、1Password 部署设置和模型路由保留。修复两个现有 host 构建阻塞：缺失的发布分发标签方法及过时的许可证测试导入。预发布选择 npm 的 `next` 标签，不提升 `latest`；本次变更不发布任何包。

部署已启用的[项目工具](../../../../packages/workspace/project-tools/README.zh.md) 通过必需的 `workspace/project` 会话事件保存完整且检查修订号的计划。现有持久化服务负责磁盘持久性。缺少写入者或刷新失败会报错；调用方重新读取，而不是盲目重复保存或外部操作。任务依赖必须无环，并引用现有任务和来源。产物位置与完成状态仍为报告的事实，不是独立核验或业主验收。

Jev 在一个请求中用独立 Choice 问题分类有界文本章节。集成固定 `jev-1.14.0`；部署必须提供置信度阈值。日志记录不含密钥的精确请求与响应。提供者凭据保留在服务端。标准部署使用只读保险库引用；若没有 1Password CLI，`WA_CREDENTIALS_MODE=env` 显式选择现有环境/存储/.env 凭据模式。两个提供者密钥须位于受保护的服务环境中；默认只读保险库模式保持不变。企业覆盖配置启用实验性图像检查与可选较大文本批次。PNG/JPEG 通过文件系统提供者读取，文件上限为四 MiB；哈希、内容和精确问题保留以供重建。图像仅发送图像启用请求头；较大文本仅在显式要求且超过常规字节上限时发送长上下文请求头。禁用路径在执行器中拒绝。部署阈值 0.9 是临时复核策略，未经校准，不授权操作。此消费者使用现有凭据和工具服务；不新增连接代理，也不替代受保护工具执行。

## 考虑的替代方案

**仅使用兼容端点。** 这会使原生 v2 实现脱离被测试的部署，并模糊提供者特有的流行为。

**让 Jev 生成项目计划。** Jev 提供类型化判断。Cohere 负责综合、工具选择，以及依据企业证据修订开放式计划。

**自动部署十六个工作代理。** [Cohere 研究](https://cohere.com/blog/lessons-from-scaling-teams-of-frontier-coding-agents) 衡量编码任务。规划结果支持受控的 RFP 实验，而非生产工作代理数量或假定成本降低。独立章节判断批量执行；可选覆盖配置也通过现有子代理工具挂载只读 `project_explore` 工作代理，每步最多两个并行工具调用，禁止递归与后台启动。工作代理继承 Cohere 路由；RFP 工作代理基准与较便宜模型选择仍需单独评估。

## 后果

真实 473 页 RFP 测试覆盖 85 批 Jev 分类、启用图像请求头的 Choice/Noul/Box，以及聚焦与 100 页长上下文比较。API 四舍五入后的概率在两位小数误差范围内保留。端到端测试也暴露了不透明检查点参数；工具现公开完整嵌套结构，并拒绝空任务列表。实际 harness 工具测试通过在线 API 覆盖图像与较大文本请求。RFP 构建器写入四份草稿和有任务的计划，但来源审核发现无依据措辞与引用错位：执行成功不等于提案验收。无密钥测试覆盖有任务检查点的磁盘恢复；完整 RFP 运行在恢复对话后才创建有任务的计划。

在线合成样本检查覆盖 Jev 1.14 分类，以及 Cohere 工具调用后从磁盘继续对话。无密钥检查覆盖真实 Loader 组合、修订冲突、依赖拒绝及带引用批量分类。构建后的 CLI 录制并无密钥回放项目检查点对话。Pi 失败对话显示 Cohere 在 strict_tools=true 时拒绝含 oneOf 的工具参数；原生适配器默认关闭严格模式。Pi 上的直接 API 探测验证 Jev 凭据和使用该参数结构的原生 Cohere 工具调用。更新后的 harness 仍需在 Pi 上安装并验证服务。SSH 策略修复将操作者现有 GitHub 身份加入受管 SSH 主机，不扩大 root 权限；其验证独立于仓库构建。跨设备项目、后台调度、解析器集成、独立产物核验、已标注阈值校准和 RFP 工作代理基准不属于已实现工具。现有提供者目录决策仍有效；此记录增加协议与项目行为，并未取代它们。
