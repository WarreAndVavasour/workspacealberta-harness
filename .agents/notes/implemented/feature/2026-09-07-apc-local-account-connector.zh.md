# Agent Note: APC 本地账户连接器

Status: implemented

[English](2026-09-07-apc-local-account-connector.md) | 中文

## Problem

公共采购搜索无法提供需要 APC 身份验证的附件。供应商登录和验证需要用户操作，而商机记录必须在临时处理环境结束后保留。

## Decision

[APC 连接器](../../../../integrations/apc/README.zh.md) 在用户桌面上管理专用的持久化 Chromium 配置文件。现有 stdio MCP 客户端向 Cohere 提供固定的连接、状态、下载和继续工具。用户在 APC 页面输入凭据，工具返回状态和文件凭据，而非浏览器会话数据。可选部署配置不改变 agent loop 或默认工具组合。

待处理的商机编号及按内容寻址的文件保存在浏览器进程之外。只有全部列出的文件下载完成后，清单才标记为完整。继续操作重新获取当前列表并保留旧内容版本。工具说明和用户指南明确告知 APC 下载会自动表达兴趣。

## Alternatives considered

**在 CI 中保存密码。** 密码不能满足 APC 的交互验证要求，还会将供应商账户引入共享构建环境。

**在 E2B 内进行身份验证。** 沙箱销毁会使交互登录和账户持久化更复杂。E2B 可以处理下载的文件，无需持有门户凭据。

**集成内部签名 URL API。** APC 浏览器在签发下载 URL 前处理身份验证。通过可见下载操作，可避免依赖未公开的凭据交换协议。

## Consequences

浏览器必须运行在用户可访问的图形桌面上。登录由 harness 聊天触发并交给本地浏览器，而非嵌入式设置面板。每个配置文件服务一个本地账户，多用户部署需要操作系统隔离。工具日志不含 Cookie，但同一操作系统用户的其他进程并未与配置文件隔离。自动 E2B 导入和后台轮询不属于此连接器。

## Verification

无需密钥的可运行示例使用真实 stdio MCP 入口和 Chromium 访问本地门户，检查模型可见记录、文件哈希及关闭后的文件保留。浏览器测试覆盖验证交接、重启持久化、页面变化、无效编号和保留登录页面。专用 CI 工作流安装 Chromium 并执行检查。真实 APC 兼容性及 Raspberry Pi 桌面行为仍需用户测试；这些夹具不能证明两者。
