# Agent Note: Workspace Alberta 采购流程

Status: implemented

[English](2026-09-07-wa-procurement-two-clocks.md) | 中文

## Problem

采购纠正必须改进可重复的工作流程，不能把客户历史变成全局指令。缺少资质证据可能导致错误拒绝；执行任务的 agent 如果自行修改指令，则会绕过审核。

## Decision

[部署参考](../../../../WORKSPACE_ALBERTA.md#procurement-two-files-two-clocks)在 harness 现有的项目发现目录中使用两个 skill 入口。基础 skill 管理采购流程及资源；独立调用的改进 skill 每次仅针对一个问题提出 PR，由人工合并。改进 skill 不出现在 harness 的模型目录中，并将基础 skill 作为审核材料读取，而非招标任务指令的一部分。

强制条件未知时，适配程度为不确定；确认不合格时才标为低适配。截止时间和修订以一手证据为准。调度器管理游标和未处理信号 ID，临时摘要及私密反馈不进入 git。调度器无法持久保存元数据时，重叠采集窗口和 PR 去重提供有界的替代方案。

## Alternatives considered

**提交最近信号文件。** 这可能公开私密反馈，并变成第三种持久记忆。临时运行存储和调度器记录能维持流程与客户历史的区别。

**新增 agent-loop 学习子系统。** 现有 skill 发现机制和独立调度器可以承载此流程，无需修改核心运行时行为。提示指令表达审核政策；实际强制执行需要权限受限的自动化身份。

**将未知担保条件视为低适配。** 能力或要求未知不等于不合格。评估规则仅在确认不匹配时使用低适配。

## Consequences

仓库提供流程及部署指令，不提供招标信息订阅器或设备群更新器。计划运行需要可用的执行主机和 GitHub 访问权限。合成示例支持人工流程审核，但不能证明模型遵循规则。没有修改已组装应用的提示、运行时包或默认提供方，因此不适用新的运行时对话快照。真实招标行为和审核身份限制仍需在部署中验证。
