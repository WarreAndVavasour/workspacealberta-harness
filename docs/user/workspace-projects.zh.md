# 持续推进企业项目

[English](workspace-projects.md) | 中文

一个企业项目使用一个对话：例如 RFP 响应、新服务或需要证据与反复业主输入的其他交付物。主模型使用原生 Cohere v2 工具调用。Jev 可在主模型制定和修订计划前分类独立来源章节。

## 启用文档资料分类

[企业部署覆盖配置](../../workspace-alberta.patch.yml) 使用 `jev-1.14.0` 启用四个项目工具、图像检查和可选较大文本批次。它通过现有只读 1Password 提供者，将 `TYPESAFE_API_KEY` 映射到 Agent Keys 中的 Jev 项目。Pi 服务账户须有该保险库读取权限。配置的 0.9 复核阈值是临时策略；请用已标注客户文档调整。分类从不授权操作。可选[工作代理覆盖配置](../../apps/cli/config/examples/workspace-project/cordis.patch.yml) 在部署覆盖配置后添加只读探索代理。

Pi 若没有 1Password CLI，在服务环境中与 `COHERE_API_KEY`、`TYPESAFE_API_KEY` 一起设置 `WA_CREDENTIALS_MODE=env`。企业覆盖配置将选择现有本地凭据提供者，包括其受保护 `.env` 支持。无需新增提供者或启动参数。未设置此选项时，标准模式仍为只读 1Password。不要将密钥值放入聊天或 Git。

[包参考](../../packages/workspace/project-tools/README.zh.md) 定义配置和失败行为。这些工具需要基础配置的会话持久化。重建或重启 Pi 时保留同一持久化 harness home；重建代码不需要删除对话。

## 推进到交付物

1. 使用可用的 MCP 或文件系统工具检索真实来源文档和公司证据。保留文件位置、内容哈希及页码或章节引用。将文档解析为文本章节；Jev 不能替代 PDF 解析器。
2. 以有界批次调用 `project_classify_sections`。对绘图、扫描表单或视觉表格，先通过可用文档工具将 PDF 页面渲染为 PNG/JPEG，再向 `project_inspect_image` 提供本地 `file_path`、`sourceId` 和精确 `location`，并对照图像复核 Box。仅在需要较大文本批次时使用 `useLongContext: true`；超过常规请求限制才发送长上下文请求头。独立章节问题共享一次 TypeSafe 请求。低置信度和 `other` 分类需要复核。不丢弃未分类章节，也不将分类分数变成资格决定。
3. 由 Cohere 根据来源、分类、企业事实和已发现工具形成计划。调用 `project_read`，然后使用预期修订号通过 `project_checkpoint` 保存完整计划。记录依赖、验收标准、阻塞项和未知事实。
4. 通过现有受保护工具执行已就绪任务。保存产物位置和进展。工具错误或中断请求不证明外部操作未完成：重试前检查目标位置。
5. 暂停后在同一对话继续。恢复工作前读取已保存项目。新对话不会自动继承另一项目的检查点。协调修订冲突，不覆盖新状态。
6. 根据来源和任务验收标准验证交付物。记录最终产物及未解决问题。向外提交前通过现有交互和权限流程获得业主批准。记录的 `completed` 任务仅为调用方报告，不证明业主验收。

## 单独评估规划工作代理

可选覆盖配置还通过现有进程内子代理工具提供 `project_explore`。工作代理继承父代理的 Cohere 路由，只能读取和搜索本地文件（`read`、`glob`、`grep`），不能继续委派。覆盖配置允许每步两个可安全并行的工具调用，并禁用后台工作代理启动。将文档检索到本地后，请主代理在同一步分配独立且带引用的探索任务。这实现并行规划，同时不给工作代理写入或提交工具。它不会自动选择较便宜的模型、设置项目总预算或证明研究结果可迁移。

Cohere 的[代理团队研究](https://cohere.com/blog/lessons-from-scaling-teams-of-frontier-coding-agents) 测试编码代理，而非采购交付。其规划工作代理结果启发 RFP 实验：比较单个 Cohere 主代理、带并行文档探索的主代理，以及带 Jev 章节判断与并行探索的主代理。使用同一来源包和验收评分表。衡量强制要求召回率、来源准确性、无依据公司声明、业主修正、交付产物、延迟和实际推理用量。工作代理发现应引用证据；主代理整合计划并负责外部操作。编码基准不能证明 RFP 质量或成本优势。

[Jev 1.14](https://typesafe.ai/blog/jev-1-14) 图像和长上下文选项仍属实验性质。图像工具发送 `TypeSafe-Danger-Zone-Images: true`；显式要求的较大文本请求发送 `TypeSafe-Danger-Zone-Long-Context: true`。普通文本批次均不发送这两个请求头。真实文档测试覆盖两个实际 harness 工具。四个来源核对问题在聚焦和 100 页输入中给出相同判断，但长上下文消耗更多 token。小样本不能证明准确率或质量优势。即使执行测试通过，草稿生成仍有无依据措辞和引用错位，因此须审核来源。

## 诊断中断对话

调整限制前检查最后提交的轮次和服务日志。区分提供者 HTTP 429、配额拒绝、上下文溢出、输出 token 上限、流超时、工具超时与服务重启。原生适配器在错误中保留 HTTP 状态，以便 harness 分类。单请求限制并不定义项目寿命。将来源文档和检查点状态放在单个请求上下文预算之外；不要提高所有限制来掩盖故障。
